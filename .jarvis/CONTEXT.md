## Architecture Summary

Jarvis-Matrix is a central orchestrator that sits between a human developer (working in any of four supported IDEs) and a library of six specialized plugins cloned on disk. It does three things: it routes slash commands to the right plugin skills, it manages persistent memory across sessions via three Obsidian-compatible brain files, and it dispatches sub-agents in parallel waves to execute implementation plans.

The project contains no application runtime code. Every file is either a markdown skill definition, a markdown agent definition, a shell script for infrastructure operations, a JSON configuration file, or a template for generated documents. The actual capabilities come from the external plugin library at `~/.gemini/config/github-plugins/develop/` — Jarvis reads from that library but never writes to it.

The routing layer works through lazy-loading: on each `/jarvis-*` invocation, the orchestrator consults `config/registry.json` to find the exact SKILL.md path needed, reads only that file, and injects it into the active agent context. This keeps token consumption proportional to the task rather than the total plugin surface.

The memory system uses three markdown files with `[[WikiLink]]` cross-references. JARVIS_MEMORY.md holds global rules that span all projects. CONTEXT.md (this file) holds a structural snapshot of one project. PROJECT_MEMORY.md holds project-scoped specs, conventions, and blame entries. Every write operation preserves existing WikiLinks and adds new ones for any cross-references introduced.

The build pipeline follows a DAG-based wave execution model. Specs are captured through `/jarvis-spec` at ≥95% confidence. Plans decompose specs into numbered atomic task files with explicit `depends_on` fields. `/jarvis-build` groups independent tasks into parallel waves, dispatches one `jarvis-builder` sub-agent per task, and gates on wave completion before starting the next. Checkpointing and resume are built in: stopping mid-build records partial progress, and restarting skips completed tasks and resumes from checkpoints.

Token compression is applied automatically at every stage using ponytail (scope minimization at three levels) and caveman (sub-agent communication compression at three modes). The `jarvis-compressor` sub-agent assigns the optimal combination per task based on a decision matrix that factors in execution phase, file count, and task complexity.
