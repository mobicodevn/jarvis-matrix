# Jarvis-Matrix

A central multi-agent orchestrator and dynamic routing plugin for AI coding assistants.

Jarvis connects your local plugin library to your active workspace. It reads project architecture, manages persistent memory across sessions, routes tasks to specialized plugins, and dispatches sub-agents in parallel waves. Works natively in Antigravity, and generates adapters for Cursor, Claude Code, and Codex.

---

## Architecture

```
┌─────────────────────────────────────────────────────┐
│  User via IDE (Antigravity / Cursor / Claude / Codex) │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│               Jarvis-Matrix Core                      │
│   Dynamic Router → Skill Registry → Sub-Agent Pool   │
│                    ↕ Memory Sync                      │
│  JARVIS_MEMORY.md · CONTEXT.md · PROJECT_MEMORY.md   │
└──────────────────────┬──────────────────────────────┘
                       │ lazy-load only required skills
┌──────────────────────▼──────────────────────────────┐
│              github-plugins/ Library                  │
│  Understand-Anything · graphify · humanizer           │
│  ponytail · caveman · agent-skills                   │
└──────────────────────────────────────────────────────┘
```

The router never pre-loads all skills. It reads `config/registry.json`, identifies the exact SKILL.md files required for the current command, and loads only those into context.

## Quick Start

### 1. Install Plugins

Clone the plugin repos you want Jarvis to use:

```bash
mkdir -p ~/.gemini/config/github-plugins/develop
cd ~/.gemini/config/github-plugins/develop

# Recommended set:
git clone https://github.com/your-org/Understand-Anything
git clone https://github.com/your-org/ponytail
git clone https://github.com/your-org/caveman
git clone https://github.com/your-org/agent-skills
git clone https://github.com/your-org/humanizer
git clone https://github.com/your-org/graphify
```

### 2. Run Setup

Open any AI coding session and run:

```
/jarvis-setup
```

Setup takes under 30 seconds. It validates your plugin library, builds the registry, initializes your global brain, and generates IDE adapters.

### 3. Analyze Your Project

Navigate to a project and run:

```
/jarvis-understand
```

This runs Understand-Anything + graphify on your project and produces `.jarvis/CONTEXT.md` — a structured architecture graph your AI assistant can load in any future session.

## Memory System

Jarvis uses three Obsidian-compatible brain files with WikiLink cross-references:

### JARVIS_MEMORY.md (Global)

Located at `~/.gemini/config/plugins/jarvis-matrix/JARVIS_MEMORY.md`.

Contains:
- **Global Coding Standards** — rules that apply to every project
- **Orchestrator Routing Rules** — how Jarvis routes to plugins
- **User Preferences** — default compression level, planning depth, IDE
- **Plugin Version Log** — version + sync date per plugin
- **Global Blame Log** — cross-project post-mortems

Managed via `/jarvis-memory`. Read by every `/jarvis-*` command.

### CONTEXT.md (Project Architecture)

Located at `<project-root>/.jarvis/CONTEXT.md`.

Contains a structured knowledge graph of your project: architecture summary, module dependency map, symbol index, community clusters, and analysis notes (god nodes, cycles).

Generated by `/jarvis-understand`. Updated incrementally by `/jarvis-refresh`.

### PROJECT_MEMORY.md (Project Brain)

Located at `<project-root>/.jarvis/PROJECT_MEMORY.md`.

Contains:
- **Project Specs Vault** — validated specs from `/jarvis-spec`
- **Project Rules & Conventions** — coding standards specific to this project
- **Business Logic Constraints** — invariants that must not be broken
- **Active Plan Status** — current plan progress
- **Project Blame Log** — project-specific post-mortems

Managed via `/jarvis-project-memory`. Every write cross-links to CONTEXT.md.

## Configuration

`config/jarvis.config.json` (written by `/jarvis-setup`):

```json
{
  "plugins_root": "~/.gemini/config/github-plugins/develop",
  "detected_ides": ["antigravity", "cursor"],
  "setup_completed": true,
  "setup_date": "2026-10-24T13:00:00Z"
}
```

`config/registry.json` (auto-generated, do not edit manually):

The registry indexes every available skill, agent, entry point, and output format across your plugin library. Rebuilt by `/jarvis-update` or by running `scripts/build-registry.sh <plugins-path>` directly.

## Compression

Jarvis applies token compression automatically using ponytail and caveman:

| Phase | Default | Max |
|-------|---------|-----|
| Spec | None | None |
| Plan | ponytail-lite | ponytail-full |
| Build | ponytail-full + caveman | ponytail-ultra + ultracave |
| Review | ponytail-lite | ponytail-full |
| Understand | ponytail-full | ponytail-ultra + caveman |
| Sub-agent comms | caveman | ultracave |

Override defaults in `JARVIS_MEMORY.md → User Preferences → default_compression`.

## The Obsidian Brain

The three memory files use `[[WikiLink]]` syntax for bidirectional linking — the same format Obsidian uses. You can open `~/.gemini/config/plugins/jarvis-matrix/` and your project's `.jarvis/` directory as an Obsidian vault to navigate the full knowledge graph visually.

Links resolve:
- `[[PROJECT_MEMORY.md]]` → `.jarvis/PROJECT_MEMORY.md`
- `[[CONTEXT.md]]` → `.jarvis/CONTEXT.md`
- `[[JARVIS_MEMORY.md]]` → plugin root memory

## FAQ

**Q: Do I need all 6 plugins?**
No. Jarvis works with whatever plugins you have available. Missing plugins produce a warning but don't halt operation. You'll lose the specific capabilities they provide (e.g., no graphify means no structural analysis).

**Q: Will Jarvis modify my plugin repos?**
Never. Jarvis reads from them (lazy-loads SKILL.md files) but never writes to them. All writes go to `.jarvis/` in your project or `~/.gemini/config/plugins/jarvis-matrix/` in the plugin itself.

**Q: What if CONTEXT.md is stale?**
`/jarvis-context` warns you if `analysis_hash` doesn't match the current git HEAD. Run `/jarvis-refresh` for an incremental update (only re-analyzes changed files) or `/jarvis-understand` for a full re-analysis.

**Q: Can I use this across multiple projects?**
Yes. `JARVIS_MEMORY.md` is global and shared. Each project gets its own `CONTEXT.md` and `PROJECT_MEMORY.md` in its `.jarvis/` directory. The cross-workspace cache means analysis results persist even if you switch between projects.

**Q: What's the difference between `/jarvis-memory` and `/jarvis-project-memory`?**
`/jarvis-memory` manages global rules that apply to all projects. `/jarvis-project-memory` manages rules scoped to one project. Global rules override project rules — use project memory for domain-specific conventions.
